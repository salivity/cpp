C++ Function Stack Frame Setup and Destruction

When a standard function invocation occurs in C++, the program relies on an execution stack to manage local state, execution flow, and object lifecycles. This article explains the technical mechanics of stack frame creation and destruction, tracing the exact sequence of events from parameter passing and frame pointer initialization to C++ destructor invocation and return-address resolution under standard modern application binary interfaces (ABIs).

1. Preparation by the Caller (Call Site)

Before control transfers to the called function (the callee), the calling function prepares the environment:

  • Argument Evaluation and Placement: Function arguments are evaluated. Depending on the architecture and ABI (such as x86-64 System V or Microsoft x64), the first few arguments are loaded directly into dedicated CPU registers. Any remaining arguments are pushed onto the stack in reverse order (right-to-left).
  • Return Address Storage: The caller executes a CALL instruction. This instruction automatically pushes the memory address of the next instruction (the return address) onto the stack and jumps to the entry point of the callee.

2. Stack Frame Setup (The Callee Prologue)

Once execution enters the callee, the function's generated assembly begins with a sequence known as the function prologue:

  • Preserving the Base Pointer: The callee saves the caller's base/frame pointer (e.g., RBP) by pushing it onto the stack.
  • Establishing a New Frame Pointer: The current stack pointer (RSP) is copied into the base pointer register. This establishes a fixed anchor reference point used to access function parameters and local variables via fixed offsets.
  • Allocating Stack Space: The stack pointer is decremented to reserve enough contiguous bytes for the function's local primitive variables, temporary evaluations, and object storage.
  • Preserving Callee-Saved Registers: If the function modifies non-volatile registers (registers that the calling convention requires be preserved across calls), their current values are pushed onto the stack.
  • C++ Object Construction: For any non-trivial local C++ objects, the compiler inserts calls to their respective constructors, initializing the memory allocated within the newly established stack frame.

3. Function Execution

During execution, the program references local variables relative to the base pointer (negative offsets) and stack-passed parameters (positive offsets). In optimized builds without frame pointer omission disabled, the base pointer may be omitted, and references are calculated directly relative to the stack pointer.

4. Stack Frame Destruction (The Callee Epilogue)

When the function completes or encounters a return statement, the runtime tears down the frame in exact reverse order of its creation:

  • C++ Destructor Invocations: The compiler guarantees that destructors for automatic (local) objects with non-trivial destructors are invoked. These destructors execute in the strict reverse order of the objects' construction.
  • Return Value Handling: If the function returns a value, it is placed in an assigned register (such as RAX/RDX for primitives and pointers). For large objects that cannot fit into registers, the caller typically passes a hidden pointer to reserved memory where the callee constructs the return object directly.
  • Restoring Callee-Saved Registers: Any non-volatile registers saved during the prologue are popped off the stack back into their hardware registers.
  • Deallocating Stack Space: The stack pointer is restored to point to the base pointer, effectively discarding all local variable allocations in a single step.
  • Restoring the Caller's Base Pointer: The saved base pointer of the caller is popped off the stack, restoring the caller's frame context.

5. Control Return to Caller

  • Executing the Return Instruction: The callee executes a RET instruction. This instruction pops the return address that was saved during the initial CALL off the stack and loads it into the instruction pointer (RIP), resuming execution in the calling function.
  • Caller Stack Cleanup: If the calling convention dictates caller cleanup (such as the legacy 32-bit cdecl), the caller increments the stack pointer to discard any arguments that were passed via the stack. In standard modern 64-bit ABIs, register usage and fixed conventions minimize the need for post-call stack adjustments.
